1. 快速启动命令速查（建图 / 存图 / 定位）

来源: 启动命令速查.md

快速启动命令速查（建图 / 存图 / 定位）

localize.launch 不绑定某个建图 launch，二者通过地图文件 comp.yaml 配对。 建图与定位互斥——都发 map→odom，同一时间永远只能起一个。

0. 清空残留进程（每次重启前必做）

# 上次没关干净的 move_base / amcl / 雷达会残留, 抢 /dev/abotlidar 串口
# -> 新 localize 收不到 /scan -> amcl 不发 map->odom -> "map does not exist" / costmap 超时
killall -9 roslaunch rosmaster rosout rplidarNode amcl move_base map_server nodelet 2>/dev/null
pkill -9 -f "rplidar|amcl|move_base|map_server" 2>/dev/null
sleep 1

报错 No laser scan received ... on /scan + target_frame map does not exist (before running costmap) 就是残留进程没清导致的：localize.launch 本身没有 costmap，一旦出现 costmap 报错=有旧 navigate.launch（带 move_base）还活着，且它抢着雷达串口让新雷达开不了 → /scan 无数据 → amcl 不发 map→odom。先执行本节再走下面时序。

编译

cd ~/catkin_ws && source /opt/ros/melodic/setup.bash && catkin_make

只编译单个包：

cd ~/catkin_ws && source /opt/ros/melodic/setup.bash && catkin_make --only-pkg-with-deps <包名>

完整时序

# 1. 建图（gmapping 或 cartographer 二选一，都先起 bringup）
roslaunch abot bringup.launch
roslaunch abot lidar_slam.launch          # 或 cartographer_slam.launch

# 2. 建好后存成 comp（localize.launch 默认就读这个名）
rosrun map_server map_saver -f $(rospack find abot)/maps/comp

# 3. 定位（与建图互斥，二选一，都发 map→odom）
roslaunch abot bringup.launch
roslaunch abot localize.launch            # 读 comp.yaml，amcl 初值 (0,0,0)

运动执行（cmd_vel 原语，绕开 move_base）

定位起好后用以下脚本发 cmd_vel，都只沿 xy 轴走、锁航向，不碰 TEB/DWA：

脚本 用途 前置 位姿来源
goal_nav.py 手动导航：rviz 点目标 → A* 全局规划 → 逐段执行 bringup + localize map→base(amcl)
auto_task_runner.py 多点航线 + 抓放（读 waypoints.yaml） bringup + localize map→base(amcl)
seven_point_test.py 7 点可达性测试（纯导航） bringup + localize map→base(amcl)
ten_point_odom_race.py 10 点纯里程计保底（定位栈挂了也能跑） 仅 bringup odom→base(EKF)

手动导航 goal_nav.py

rosrun abot goal_nav.py                 # 或 python2 goal_nav.py
  • rviz 操作：① 加一个 Path display，topic 设 /goal_nav/path；② 点工具栏 2D Nav Goal 在地图上发目标 → 显示规划线 → 车按 x/y 直线段开过去。
  • A* 在 /map 栅格上算路，障碍按 ~inflation_radius（默认 0.20m）膨胀避开挡板/围栏；4 连通只出直线段，严格不斜穿。
  • 是静态地图上的确定性全局规划，不加载 TEB/DWA 的反应式局部规划器。

关键点

  • 建图 launch 用 basename 启动：roslaunch abot lidar_slam.launch（不带 slam/ 子目录），否则报 RLException。
  • 起点摆位：localize 的 amcl 初值写死 (0,0,0)，所以建图起点必须摆在比赛原点、车头朝 +x，使地图原点 = (0,0) = amcl home 对齐。
  • 运动执行：定位起好后用 auto_task_runner.py 自闭环发 cmd_vel，不经 move_base/TEB/DWA。
  • ⚠️ cartographer 路径隐患：车上 rplidar_lds.lua 仍是旧配置 provide_odom_frame=true，现在跑 cartographer 会和 EKF 双发 odom→base 冲突；gmapping 路径不受影响。

2. 比赛规则（最终目标 · 硬约束）

来源: 比赛规则.md

室内移动抓取搬运赛 — 比赛规则

这是 small-car 项目的最终目标。仓库里的导航、定位、抓取全部为它服务。 工程上「只沿 xy 轴走、不得漂移、原地转」不是偏好，是不撞挡板的生存约束（见文末「对工程的约束」）。

1. 场地

项目 值
场地尺寸 3.6 m × 3.6 m
四周围栏 高 30 cm
起点 左下角，40 × 40 cm
终点 右下角，40 × 40 cm
挡板 (divider) 长 2.4 m，分隔列
  • 6 个任务点排成 2 行 × 3 列：上排 1 / 3 / 5，下排 2 / 4 / 6。
  • 每个任务点前有 40 × 40 cm 的「搬运点」，机器人必须完全进入才算到达。
  • 搬运区域（蓝，抓取）/ 放置区域（紫，放置）宽 23 cm。

   ┌─────────┬─────────┬─────────┐
上排│  点1 抓  │  点3 抓  │  点5 抓  │

   └─────────┴─────────┴─────────┘
 [起点 左下]              [终点 右下]

2. 任务流程（固定顺序）

起点 → 搬运点1(抓) → 点2(放) → 点3(抓) → 点4(放) → 点5(抓) → 点6(放) → 终点
  • 奇数点 1 / 3 / 5 = 抓取（搬运区域）
  • 偶数点 2 / 4 / 6 = 放置（放置区域）
  • 抓取目标物品赛前由裁判随机抽取公布，所以物体关键词运行时才喂给 vl_locate。

对应代码：scripts/auto_task_runner.py + scripts/waypoints.yaml。 waypoints.yaml 必须填真实的 6 个搬运点坐标，grab / place 交替，最后到终点。

3. 得分

项目 分值
到达每个任务点 5 / 点
抓取成功 10 × 3
放置成功 10 × 3
到达终点 10
技术文档 / 答辩 10
  • 两次机会取最高分。
  • 同分比用时。

4. 致命终止条件（碰一下就结束比赛）

触发任意一条，整场比赛立即结束、该次成绩定格。

  • ⚠️ 触碰围栏 / 挡板 / 障碍物 → 立即结束
  • ⚠️ 启动后 30 s 未动 / 状态 30 s 无变化 → 结束（程序死机同理）
  • 队员进场、举手示意、机器人完全进入终点 → 结束

5. 对工程的约束（Why & How）

Why：碰任何东西 = 直接判负。这是「只沿 xy 轴走、不得漂移、原地转」的硬原因——不是偏好，是生存约束。

How to apply：

  1. 不贴挡板走。路线留足余量，别让 move_base 的 reactive 避障逼近障碍（碰 = 结束，风险高）；L 形 leg 走安全车道中线。
  2. fail-fast，保持连续运动。「30 s 不动 = 判负」→ goal 卡住会触发判负，超时设置不能太长，卡住要快速放弃 + 继续动。
  3. 抓放精度要够。搬运点 40 × 40 cm 必须完全进入才算到达。

相关背景见 reports/调参极限分析报告.md（轨迹漂移分析）、logs/2026-05-26_SLAM建图与局部规划器解耦.md（绕开 move_base 的原语控制方案）。

3. 项目总览 README

来源: README.md

Small Car — ABOT M1 ARM 智能小车

基于 ROS 的自主导航 + 视觉抓取 + 机械臂操控实验平台 属于 三仓库生态系统 的工程代码仓库

比赛目标与规则

本项目的最终目标是室内移动抓取搬运赛：3.6×3.6 m 场地，起点 → 6 个搬运点（奇数抓 / 偶数放）→ 终点。 碰围栏/挡板 或 30s 不动即立即判负——这是工程上坚持「只沿 xy 轴走、不漂移、原地转」的硬约束。

完整场地、任务流程、得分与终止条件见 比赛规则.md。

硬件平台

  • 底盘: ABOT M1 ARM 麦克纳姆轮（四轮）
  • 计算: NVIDIA Jetson Nano（Tegra X1，Ubuntu 18.04 / ROS Melodic）
  • 传感器: 思岚 RPLidar C1 | Astra RGBD 深度相机 | MPU6050 IMU（9轴）
  • 执行器: 六自由度机械臂（吸盘抓取）
  • 连接: 局域网 SSH（192.168.36.46 或 192.168.43.211，用户 abot）

第一章 机器人硬件介绍

1.1 硬件框架

机器人硬件采用STM32F1驱动板组成系统通信框架

1.2 主控制器

ROS控制器采用Jetson nano主控，运行Ubuntu18.04系统，安装有ROS机器人操作系统，ROS版本为Melodic版本。

1.3 底层驱动板

底层驱动板为自主研发的机器人驱动板，跟上层主控采用ROSSERIAL协议通信，驱动板MCU采用STM32F103RCT6芯片，板载MPU6050 IMU角速度陀螺仪传感器。

1.4 激光雷达

思岚A1/A2雷达，可实现12M测距范围，5.5HZ扫描频率，8000次/秒测量频率。

1.5 深度摄像头

RGBD深度摄像头，RGB是彩色图像，D是depth（深度图像），可用于空间三维点云重建、视觉SLAM、视觉导航避障等应用。

第二章 开箱使用说明

2.1 使用前准备工作

第三章 ABOT ROS 源码文件说明

3.1 ABOT ROS 机器人文件结构说明

import numpy as np

cap = cv2.VideoCapture(0)
ret, frame = cap.read()

roi = frame[r:r+h, c:c+w]
hsv_roi = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv_roi, np.array((0., 60., 32.)), np.array((180., 255., 255.)))

cv2.normalize(roi_hist, roi_hist, 0, 255, cv2.NORM_MINMAX)

2. 导航与定位

2.1 AMCL 初始位姿错误导致粒子发散

症状：小车启动后 AMCL 长时间不收敛，位姿漂移严重。

根因：initial_pose_x/y/a 设为 (0,0,0)，但小车实际停放位置不是原点。AMCL 在错误位置初始化粒子，需要大量激光匹配才能修正。

解法： - 在 amcl.launch 中设置正确的初始位姿（当前: x=0.6, y=-0.4, yaw=0） - 或启动后用 rostopic pub /initialpose 手动设定 - 使用 patrol_run.sh 中的自动 initialpose 流程

2.2 move_base 耗时过长

症状：move_base 规划+执行一个目标点耗时远超预期，controller 反复调整。

根因： - controller_patience 设为 15 秒，每次调整都等到超时才放弃 - TEB 的 weight_max_vel_theta 太小（=1），规划器倾向旋转而非平移

解法： - controller_patience → 5 秒（move_base_params.yaml） - weight_max_vel_theta → 10（teb_omni_planner_params.yaml） - oscillation_timeout → 15（留足够时间恢复）

2.3 激光雷达扫描到车体导致避障异常

症状：小车原地打转或路径规划避开"自己"，因为激光扫到了车体边缘。

根因：laser_filters 的 min_x 不够大，车体部分被激光束覆盖。

解法：x4_laserfilter.yaml 中 min_x → -0.25（遮掉更多车体前方区域）。

2.4 Cartographer tracking_frame 配错

症状：建图时轨迹扭曲，点云无法对齐。

根因：tracking_frame 和 published_frame 设为 laser，应该是 base_footprint。Cartographer 需要知道机器人的坐标系而非传感器坐标系。

解法：rplidar_lds.lua 中改 tracking_frame = "base_footprint"，published_frame = "base_footprint"。

3. 硬件与通信

3.1 不同激光雷达型号波特率不同

症状：换了激光雷达后无数据输出。

根因： - A1/A2: 115200 - A3: 256000 - C1: 460800

解法：在 rplidar.launch 中切换 serial_baudrate，默认已设为 460800（C1）。

cartographer 耦合（gmapping 替代方案）

"耦合" = 时序工作流，不是同时跑（cartographer 与 amcl 仍互斥，都最终提供 map→odom）：

cartographer 建图(实时) → map_saver 存 comp.pgm/.yaml → amcl(localize.launch) 读图定位

关键修复：rplidar_lds.lua 原配置 provide_odom_frame=true + published_frame=base_footprint → cartographer 会发整条 map→odom→base_footprint，和 bringup 的 EKF（已发 odom→base_footprint）双发冲突。改为 published_frame=odom + provide_odom_frame=false → cartographer 只发 map→odom，EKF 继续管 odom→base_footprint（robot_localization 共存的标准配法）。use_odometry 暂保持 false。

存图：cartographer 的 cartographer_occupancy_grid_node 发 /map，与 gmapping 一样直接 map_saver -f $(rospack find abot)/maps/comp（不需 .pbstream，除非用 cartographer 纯定位模式）。

  1. 两个互斥模式（都发 map->odom，永远二选一）：建图 = bringup+gmapping(lidar_slam)；已知图导航 = bringup+amcl(localize.launch)。不能与 cartographer_slam/navigate.launch 叠加（amcl 与 SLAM 抢 map→odom、map_server 抢 /map、lidar 抢串口）。
  2. 数据流：轮速+IMU→[EKF]→odom→base；激光→[gmapping/amcl]→map→odom；合成 map→base 给 auto_task_runner 闭环发 cmd_vel。全程不经 move_base/TEB/DWA。
  3. 建图原点 = 比赛原点的做法：不必为挪原点单独重建；重建时把车物理摆到比赛原点、重启 bringup 归零、再起 gmapping，则地图原点=比赛原点=(0,0)，与 localize.launch 里 amcl 初值 (0,0,0) 对齐。车头朝向 = 地图 +x 轴。

5. 基于麦轮的根因排查方向

5.1 优先排查：麦轮滚子打滑

麦轮滚子（被动小轮）磨损后摩擦力下降，侧移时滚子不能有效滚动，导致实际运动方向偏离指令方向。表现与观测到的"左移超调 + 后退"一致。

验证方法： 1. 检查四个麦轮滚子外观，看有无明显磨损、裂纹、转动卡滞 2. 悬空状态下手动旋转每个滚子，感受阻力是否一致 3. 更换磨损滚子或整车麦轮后复测

5.2 优先排查：麦轮安装方向

麦轮有正反安装要求——四个轮子的滚子方向必须与底盘运动学模型一致。装错一个（例如左前轮的滚子方向镜像），MCU 仍按正确模型分解速度，但该轮实际运动方向相反，导致车身扭动和漂移。

验证方法： 1. 检查 ABOT M1 ARM 的官方麦轮安装图示 2. 确认四个轮子滚子方向是否符合标准 X 形或 O 形布局 3. 特别检查是否有轮子被拆卸后装反

5.3 里程计标定

当前 linear_scale = 1.014，未经严格标定验证。

验证方法： 1. 让小车在直线上走 1m，测量实际距离，linear_scale *= 目标/实际 2. 侧移测试：让小车纯侧移 1m，单独标定侧移方向的 scale 3. 角速度标定：旋转 360°，比较 odom 输出与实际角度

5.4 轮距/轴距参数

ABOTMODEL=x4 对应的轮距（track）和轴距（wheelbase）参数需要与实际测量值一致。偏差会导致旋转和侧移时的运动学分解出错。

验证方法： 1. 实测小车四个麦轮中心之间的横向和纵向距离 2. 对比 ABOTMODEL=x4 的配置文件中的参数值 3. 不一致则修正参数或改用自定义模型

5.5 四轮接地均衡性

麦轮需要四个轮子均匀接地，任何一个悬空或压力不均都会导致该轮滚子打滑加剧。

验证方法： 1. 在平坦地面上按压小车四角，感受悬挂回弹是否一致 2. 在小车四角各放一张纸，看是否能抽出（压力测试） 3. 调整悬挂或更换场地

5.6 AMCL 位姿估计噪声

Run 9（最佳，不可复现）提示 AMCL 位姿估计可能存在偶然波动，不一定是控制策略在起作用。

验证方法： 1. 在已知位姿下（如靠墙对齐）做闭环测试，排除 AMCL 噪声 2. 比较 /odom 和 /amcl_pose 的漂移量 3. 用 rqt_plot 实时观察 pose 方差

自动建图和保存功能使用指南

本指南介绍如何使用自动建图和保存功能，在闭合空间内自动创建地图并保存。

功能概述

自动建图和保存功能包含以下组件：

  1. auto_map_save.py - 核心Python脚本，负责启动SLAM建图、等待指定时间后停止建图并保存地图
  2. run_auto_map.sh - 启动脚本，简化运行过程
  3. auto_map_save.launch - ROS launch文件，用于启动自动建图节点

使用方法

方法1：使用Launch文件（推荐）

roslaunch abot auto_map_save.launch map_save_time:=120 map_name:=my_map

参数说明： - map_save_time：建图时间（秒），默认120秒 - map_name：保存的地图名称，默认为auto_map

方法2：使用启动脚本

chmod +x ~/catkin_ws/src/abot_project/abot/scripts/run_auto_map.sh
~/catkin_ws/src/abot_project/abot/scripts/run_auto_map.sh 120 my_map

方法3：直接运行Python脚本

rosrun abot auto_map_save.py _map_save_time:=120 _map_name:=my_map

工作流程

  1. 启动SLAM建图（使用lidar_slam.launch中的配置）
  2. 机器人在环境中移动进行探索建图
  3. 等待指定时间后自动停止SLAM
  4. 使用map_server的map_saver保存地图
  5. 地图文件保存到maps目录中

注意事项

  1. 确保机器人在闭合空间内，以便获得完整地图
  2. 建图时间应根据环境大小适当调整
  3. 确保ROS环境已正确设置
  4. 机器人需要配备激光雷达以进行SLAM建图

故障排除

  1. 如果出现路径错误，请检查launch文件路径是否正确
  2. 如果地图保存失败，请检查是否有写入maps目录的权限
  3. 如果SLAM无法启动，请确保相关依赖包已安装

10. abot 包 README

来源: src/abot_project/abot/README.md

ABot机器人自动建图包

本包提供了ABot机器人在闭合空间内自动建图并保存的功能。

功能特性

  • 自动启动SLAM建图
  • 在指定时间后自动停止建图
  • 自动保存生成的地图
  • 支持参数配置（建图时间、地图名称等）

组成部分

Python脚本

  • auto_map_save.py - 核心自动建图和保存脚本

Launch文件

  • auto_map_save.launch - 启动自动建图节点的launch文件

Shell脚本

  • run_auto_map.sh - 便捷启动脚本
  • start_auto_mapping.sh - 快速启动脚本

文档

  • docs/auto_map_guide.md - 详细使用指南

依赖项

  • ROS Melodic (Ubuntu 18.04)
  • SLAM相关包 (gmapping, cartographer等)
  • map_server包
  • 机器人硬件：激光雷达、Mecanum轮底盘

使用方法

方法1：使用Launch文件（推荐）

roslaunch abot auto_map_save.launch map_save_time:=120 map_name:=my_map

方法2：使用启动脚本

./scripts/start_auto_mapping.sh

方法3：直接运行Python脚本

rosrun abot auto_map_save.py _map_save_time:=120 _map_name:=my_map

参数说明

  • map_save_time：建图时间（秒），默认120秒
  • map_name：保存的地图名称，默认为auto_map
  • map_directory：地图保存目录，默认为包内的maps目录

地图保存位置

生成的地图文件将保存在maps目录中，包含.pgm（图像）和.yaml（配置）文件。

注意事项

  1. 确保机器人在闭合空间内，以便获得完整地图
  2. 建图时间应根据环境大小适当调整
  3. 确保机器人配备了正常工作的激光雷达
  4. 确保ROS环境已正确设置

故障排除

  1. 如果出现路径错误，请检查launch文件路径是否正确
  2. 如果地图保存失败，请检查是否有写入maps目录的权限
  3. 如果SLAM无法启动，请确保相关依赖包已安装
