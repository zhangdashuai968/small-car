> 面向：零基础新队员。终点：独立完成一次「导航 → VLM 识别 → 机械臂抓取 → 放置」的物流搬运全流程。

> 与厂商文档冲突时，以本文 + [`README.md`](../README.md) 为准（差异表见第 0 章）。
> 零基础补 ROS 语法去课堂仓 [abot_arm_learning](https://github.com/zhangdashuai968/abot_arm_learning)；本仓是战场仓。

## 第 0 章 真机档案：这台车和说明书上写的不是一回事

### 0.1 车是什么

- Jetson Nano · Ubuntu 18.04 · ROS Melodic · **Python 2.7**（车上 ROS 脚本多为 py2；conda `39` 环境是给 VLM 用的 py3.9，两套并存别搞混）
- ABOT M1 麦克纳姆轮底盘（STM32F103 + rosserial 115200）· MPU6050 IMU · RPLidar **C1** · Astra 深度相机 · xArm 六自由度机械臂
- 里程计 = 轮式编码器 + IMU 经 EKF 融合，**航向 100% 来自 IMU**
- 网络：SSH `abot@192.168.36.46`（实验室）或 `192.168.43.211`（手机热点），双网段开机随机
  （正本以 [`README.md`](../README.md) 硬件表为准）

### 0.2 厂商文档 ≠ 我们的车（差异表，先背这张）

| 厂商《实验指导书》说 | 真机实际 | 照厂商做会怎样 |
|---|---|---|
| 雷达 A1/A2（波特率 115200） | **RPLidar C1（460800）** | 调错波特率 → /scan 无数据 |
| 导航 teb / dwa 二选一 | **只用 DWA**，TEB 已弃用存档 | 去调 TEB 参数 = 浪费生命 |
| 第十章 HSV 色块 + 手眼标定抓取 | **VLM（qwen 视觉大模型）链路**，见第 5 章 | 厂商抓取章仅作原理对照 |
| ToDesk 远程桌面 | 团队用 **SSH**（Windows 免密已配好） | — |
| `abot_patrol_nav.py` 多点巡航 | `waypoints.yaml` + `auto_navigation_grasp.py`（保底 `ten_point_odom_race.py`） | — |

> 厂商指导书全文：`src/abot-m1-arm实验指导书.txt`（精简版 `src/小车实验指南技术教育详解(2).md`），13 章索引见附录 B。

### 0.3 三条铁律（每条都是"判负/白干"级别）

1. **建图与定位互斥**：gmapping 和 amcl 都发 `map→odom`，同一时间只能起一个。
2. **每次重启先清残留进程**：
   ```bash
   killall -9 roslaunch rosmaster rosout rplidarNode amcl move_base map_server nodelet 2>/dev/null
   ```
   残留进程抢雷达串口 → 新会话收不到 /scan → 一连串灵异报错（症状详见 TROUBLESHOOTING）。
3. **起点摆位**：建图起点 = 比赛原点、车头朝 **+x**。地图原点、amcl 初值全锚在这里，摆歪了后面全歪。

### 0.4 启动环境变量

```bash
export ABOTMODEL=x4 ABOTBASE=omni NAV_PATH=dwa ABOTLIDAR=rplidar ABOTIMU=mpu6050
```

一般已写在车的 `.bashrc`，上机先核对：`env | grep -E 'ABOT|NAV'`。缺任何一个 bringup 起不来。

### 0.5 裸 SSH 两个坑

- SSH 进去是干净 shell，跑 ROS 前先 `source /opt/ros/melodic/setup.bash`（`rosversion -d` 报 unknown 就是没 source）。
- Windows 传 .py 上车注意 CRLF：报 `'python\r': No such file` 就 `sed -i 's/\r$//' 文件`，再 `python -m py_compile 文件` 验证。

## 第 1 章 连上车，把它开起来

**验收：键盘遥控小车平稳绕场地一圈回到起点。**

### 1.1 找车、连车

- 车**禁 ping**（ICMP 不通 ≠ 不在线），判在不在线用 22 端口，两个网段 IP 轮流试。
- Windows：`ssh abot@<车IP>`（免密已配）或仓库根目录 `python scripts/ssh-car.py`。
- 上车后 `hostname -I` 确认当前 IP。

### 1.2 启底盘

```bash
source /opt/ros/melodic/setup.bash
roslaunch abot bringup.launch     # 底盘+IMU+EKF；车平放地面
```

### 1.3 键盘遥控

```bash
rosrun teleop_twist_keyboard teleop_twist_keyboard.py
```

小写 `i`/`,` 前进后退，`j`/`l` 左右转；麦轮可切大写全向模式；`q`/`z` 加减速。

### 1.4 看一眼话题（养成习惯）

```bash
rostopic list
```

核心话题：`/cmd_vel` 速度命令 · `/odom` 里程计 · `/imu/data` 姿态 · `/scan` 雷达 · `/battery` 电量。

> PS2 手柄：配对后 MODE 灯长亮即手柄模式，L1 普通模式 / L2 全向模式（细节翻厂商指导书 5.1）。

## 第 2 章 标定三件套：IMU → 角速度 → 线速度

**验收：原地转一圈误差 ≤10°；走 1 米误差 ≤2cm。**

为什么标：里程计航向全靠 IMU、距离全靠编码器——标不准 → 建图歪 → 导航偏 → 抓取够不着。**顺序不能乱**。

### 2.1 IMU 校正

```bash
roslaunch abot bringup.launch                      # 终端1，车静止平放
cd ~/catkin_ws/src/abot_project/abot/param/imu     # 终端2（要加载配置）
rosrun imu_calib do_calib                          # 按提示回车走完
```

### 2.2 角速度校正

```bash
rosrun abot_nav calibrate_angular.py      # 终端2
rosrun rqt_reconfigure rqt_reconfigure   # 终端3，start_test 让车原地转一圈
```

手机指南针对比：停下指 60° = 实转 370° → `anguler_scale = 370/360 = 1.028`，填进 rqt 再测一轮，误差 <10° 收工，最后写回 bringup.launch。

### 2.3 线速度校正

```bash
rosrun abot_nav calibrate_linear.py
rosrun rqt_reconfigure rqt_reconfigure   # start_test 走 1 米，卷尺量
```

走 1.1m → `linear_scale = 1.1`。参照：当前车实测 `linear_scale = 1.014`；日常复核公式 `linear_scale *= 目标距离/实际距离`。

**验收：一张边界闭合、无重影的场地地图，存盘成功。**

## 第 4 章 导航与多点巡航

**验收：2D Nav Goal 自动到达并避障；再跑通 waypoints 巡航（`--nav-only`）。**

### 4.1 单点导航

```bash
roslaunch abot bringup.launch      # 终端1
roslaunch abot navigate.launch     # 终端2：move_base(DWA) + amcl + house.yaml，amcl 初值 (0.6, -0.4)
rviz                               # 终端3
```

rviz 里：雷达轮廓与地图不重合时先 `2D Pose Estimate` 校位姿，再 `2D Nav Goal` 发目标点。

### 4.2 AMCL 四个坑（前人拿 9.3cm→3.2cm 的误差改善换来的）

1. **yaw 必须归一化到 [-π, π]**：路点 yaw 先过 `math.atan2(math.sin(yaw), math.cos(yaw))` 再写入 yaml；>2π 的等效角会让粒子群分裂发散、误差逐点递增。
2. **静止死区**：`update_min_d=0.10`——车完全不动 amcl 不更新（`/amcl_pose` 序号卡住），微动 0.05 m/s 触发。
3. **自报精度不可信**：显示 3-4cm 时实际可能偏 50cm+，判断发散看**偏差趋势**，不看自报值。
4. **initial_pose 写实际停放位姿**：设 (0,0,0) 粒子长期不收敛。

### 4.3 多点巡航（比赛主流程的运动层）

```bash
# 前置：bringup + navigate 已起
python2 ~/catkin_ws/src/abot_project/scripts/move_base_waypoint_runner.py --nav-only
```

- 航线正本 `scripts/waypoints.yaml`；主流程 `auto_navigation_grasp.py` 内联同坐标（**改 yaml 要同步改 .py**）。
- 运动脚本在 `src/abot_project/scripts/`，不在 abot 包里——用 `python2 <绝对路径>` 跑，`rosrun abot` 找不到。
- 保底梯队：定位栈挂了 → `localize.launch` + `goal_nav.py`（原语导航）；全挂 → `ten_point_odom_race.py`（纯里程计，只需 bringup）。

## 第 5 章 VLM 抓取：让车自己认东西、自己抓

**验收：`rosservice call /vlm_detection "object_name: 'xx'"` 抓起指定物品并放到目标点。**

### 5.0 原理一页纸

```
相机 /new_topic → resize_core（ROI 裁剪+放大）→ qwen VLM（bbox）→ 归一化
    → 两点标定（像素→机械臂）→ /Pose → ZachLab_grasp 机械臂执行
```

- 识别靠**视觉大模型**（阿里云百炼 qwen，openai 兼容接口），不是传统 HSV 色块。
- **标定在 zoomed（放大后）图像空间**：`cali_*_im` 是 resize 输出图上的像素坐标，**不要**做 unzoom 反算——历史上加过反算，实测反而错，已删。
- 两点标定 = 采两组「图像像素 ↔ 机械臂坐标」对应关系，解出像素→机械臂的映射。

### 5.1 环境（已部署：了解 + 别动）

- 车上 `anaconda3`（6.5G）是 VLM 依赖，**勿删**。VLM 跑在 conda `39` 环境（py3.9：opencv 4.11 / numpy 1.23 / openai / dashscope）。
- API 配置在 `src/abot_project/vl_locate/config/vlm_params.yaml`（`api_key` / `base_url` / `model_name` / `mode` 四个字段）。
- **自己的 key 自己申请**（阿里云 → 大模型服务 → 密钥管理 → 创建 API-KEY）；**绝不把 key 写进任何会提交的文件**。
- 整车重刷系统时的重建流程（gparted 扩容 → anaconda → pip → key）见根目录《物流搬运实践快速上手指南》PDF。

### 5.2 调试标定（每台车 / 每次动过摄像头角度都要重做）

```bash
# 1. 调试开关：abot_grasp_race/launch/grasp_race.launch 里
#    calibration_mode=True、fix_grasp_mode=True（定点调试，False 是移动抓取）
# 2. 启底盘 + 调相机角度（要照到车前下方的抓取区）
roslaunch abot bringup.launch
rostopic pub -1 /servo riki_msgs/Servo "{Servo1: 88, Servo2: 20}"   # Servo1 左右 / Servo2 上下
# 3. 一键调试（车上脚本，自动开 bringup / vl_locate / grasp_race / rqt 四窗）
./2-debug.sh        # 夹爪没开先 roslaunch ZachLab_grasp grasp.launch，开完再回来
```

rqt_reconfigure 里用 x/y/z/rotary 手动把夹爪挪到**标定物正上方**，采两组点（左下角、右上角各一组）：

- 机械臂坐标：rqt 里当时的 x、y 值
- 像素坐标：`rosservice call /vlm_detection "object_name: 'apple'"`，回显 message 里的 2D 坐标

### 5.3 填参数（正本 `src/abot_project/ZachLab_grasp/config/ZachLab_params.yaml`）

| 字段 | 含义 | 某次标定的示例值 |
|---|---|---|
| `cali_1_im` / `cali_1_mc` | 左下标定点：像素 (x,y) / 机械臂 **(-y,x)** 注意轴交换 | [48, 384] / [-75, 110] |
| `cali_2_im` / `cali_2_mc` | 右上标定点：像素 / 机械臂 | [590, 111] / [120, 213] |
| `grasp_z` | 抓取下探高度 | -115 |
| `grasp_offset_x/y` | 抓取微调：整体偏后加正 x，偏左加负 y | 10 / 0 |
| `place_offset_x/y` | 放置专用微调 | 0 / -15 |
| `rotation_factor` | = abs(rotary-90)/abs(y)，多点取平均 | 0.46 |
| `max_rotation_angle` | 旋转角度上限 | 45 |

> 示例值只代表某一次标定，**每次重标都会变**——照 5.2 实测填，别抄数。

### 5.4 抓取执行与修偏

```bash
rosparam set /grab 1                                  # 1=抓取，0=放置
rosservice call /vlm_detection "object_name: 'apple'" # 名字可换（中文也行）
```

偏差大（>半个物体）→ 重标 5.2；偏差小 → 调 `grasp_offset_x/y`，每次 ±5 量级试。

## 终章 通关考核：物流搬运全流程

比赛任务：3.6×3.6m 场地，起点 → 6 个搬运点（奇数抓 / 偶数放）→ 终点。**碰围栏/挡板或 30s 不动立即判负**——所以工程上坚持只沿 xy 轴走、不漂移、fail-fast。

### 主流程（= README 快速上手）

```bash
roslaunch abot bringup.launch
roslaunch abot navigate.launch
conda activate 39 && roslaunch vl_locate vl_locate.launch      # VLM 视觉检测
roslaunch ZachLab_grasp grasp.launch                           # 机械臂
python2 ~/catkin_ws/src/abot_project/scripts/auto_navigation_grasp.py   # 10 点抓放
```

整合版（一条命令起全套，6 航点 + 蓝/红/绿方块识别）：`roslaunch abot_grasp_race cargo_handling.launch`；车上还有 `./auto_start.sh` 一键脚本（**谨慎开启**，起前确认场地清空）。

### 考核 checklist（培训者逐项打勾）

- [ ] 独立找车、连车、清残留进程、起底盘
- [ ] 遥控平稳；说得出 /cmd_vel、/odom、/scan 各是什么
- [ ] 标定三件套达验收线（一圈 ≤10°、一米 ≤2cm）
- [ ] 独立建一张闭合地图并按对的名字保存
- [ ] 单点导航 + waypoints 巡航（--nav-only）跑通
- [ ] 讲得出 VLM 链路五步，以及"标定在 zoomed 空间、不要 unzoom"
- [ ] 独立完成两点标定并正确填写 ZachLab_params.yaml（含 -y,x 轴交换）
- [ ] 全流程通关一次，不碰围栏
- [ ] 知道改完代码在 Windows 侧跑 `python -m pytest tests/`（59 例回归网）再提交
