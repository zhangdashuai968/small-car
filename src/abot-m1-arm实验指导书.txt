第一章 机器人硬件介绍
1.1 硬件框架
机器人硬件采用STM32F1驱动板组成系统通信框架
1.2 主控制器
ROS控制器采用Jetson nano主控，运行运行Ubuntu18.04系统,具体型号有差异。系统安
装有ROS机器人操作系统, ROS版本为Melodic版本,作为机器人端ROS节点控制器。
1.3 底层驱动板
底层驱动板为自主研发的机器人驱动板，跟上层主控采用ROSSERIAL协议通信，整体通信
协议基于标准ROSSERIAL协议，调用库函数API，用户可通过自定义消息来实现数据通信。驱
动板MCU 采用STM32F103RCT6芯片，板载 MPU6050IMU角速度陀螺仪传感器,支持4路直流电机
闭环驱动控制，一路超声波传感器控制，两路舵机驱动控制，一路温湿度 传感器控制， 一
路蓝牙控制， PS2手柄控制，SWD固件程序烧录口，还引出芯片富余IO口可供用户二次发用
1.4 激光雷达
思岚A1/A2雷达， ABOT ROS机器人搭载思岚A1/A2激光雷达,可实现12M测距范围,5.5HZ扫
描频率, 8000次/秒测量频率,适合室内SLAM建图，导航避障等应用场景。
1.5 深度摄像头
RGBD深度摄像头，RGB是彩色图像，D是depth，是深度图像，可用以空间三维点云重建，
视觉slam、视觉、导航 避障等应用。
1.6 其他硬件设备
12000mA锂电池、12V直流有刷电机，麦克纳姆轮，车体，PS2蓝牙手柄、排线、舵机云台
等使用目前市场同行业主流产品，不作一一介绍。
1.7 可扩展硬件
系统集成了rplidar 思岚系列、镭神C16B 16线激光雷达、Intel realsense系列驱动，
用户可以参考后面的实验指导直接使用。
第二章 开箱使用说明
2.1 使用前准备工作
ABOT ROS机器人的主控采用ubuntu18.04系统作为开发主机，所以需要具备一定的linux
基础技能，这只是上手的一个基本技能，另外ROS涉及的知识范围很广，复杂，所以大家对此
要有一定的认识，
准备使用步骤流程（这个详细操作参考使用视屏会有一个详细了解）：
1、机器人先充满电，第一次充电时间会比较长，大概需要5-8小时之间，直到充电器显
示绿灯为止，另外最好不要边 充边用，以免造成充电器烧坏。
2、开机上电后，用HDMI线连接显示器与Jetson nano进入系统桌面后，连接无线WIFI，
然后记下主控的IP，另外确 保路由器设置是静态IP形式，以防IP地址会变化。
3、准备一台Windows系统电脑，安装to desk远程桌面软件，通过识别码和密码登录到机
器人的主控系统桌面。具体操作流程如下：
（1） 打开todesk的官网 https://www.todesk.com，选择Linux版本
（2）选择立即下载，选择第二个arm64，点击所标网址下载
（3）下载完成后，找到下载文件所在的文件夹，右键打开终端，输入以下代码：
sudo apt-get install ./todesk-v4.7.2.0-arm64.deb
（4）安装完成后，输入ToDesk即可打开软件
4、接下来的操作，请按实训教程一章一章节进行。
5、另外想进阶ROS，可参考学习我们配套的学习资料，还可以参考ROS官网的教程，链接
如下：
http://wiki.ros.org/ cn/ROS/
2.2 网络环境说明
ROS基于局域网通信，请确保路由器设置成静态IP形式，主控系统和Windows系统电脑在
同一个网段下，否则会出现 通信异常。

PS2手柄控制
手柄控制是不需要任何启动任何连接，机器人上电后，手柄打开开关进行配对，配对完
成后，按下MODE键，此时手柄上方的POWER与MODE指示灯都亮了，就进入了手柄控制模式，
切记如果只有POWER灯亮，MODE灯不亮这时的 手柄控制会异常。
1、打开手柄电源
2、开始配对，按START键开始配对，按MODE键切换模式，如果两个指示灯都长亮则配对
完成并切换到手柄控制模 式，如果是一闪一闪则说明配对不成功，需要检查机器人是否上电，
或者驱动板是否坏掉
3、如何控制，L1触发普通模式，L2触发全向轮模式
普通模式：左侧L1+左遥感（上下推）为前进后退，左侧L1+右遥感（左右推）为左右旋转。
全向轮模式：左侧L2+左遥感(上下推)为前进后退，左侧L2+右遥感（左右推）为横移。

第六章 ROS SLAM
6.1 ROS机器人slam构建地图与保存
6.1.1 实验目的
熟悉机器人常见SLAM算法（gmapping、 hector、 karto、cartographer）构建地图与
保存地图步骤。
6.1.2 实验原理
(1）Gmapping
Gmapping是一种基于激光的SLAM算法，它已经集成在ROS中，是移动机器人中使用最多
的SLAM算法。这个算法已 经由Grisetti等人提出是一种基于 Rao-Blackwellized的粒子滤
波的 SLAM方法。基于粒子滤波的算法用许多加权粒子
表示路径的后验概率，每个粒子都
给出一个重要性因子。但是，它们通常需要大量的粒子才能获得比较好的的结果，
从而增
加该算法的的计算复杂性。此外，与PF重采样过程相关的粒子退化耗尽问题也降低了算法的
准确性。粒子退化 问题包括在重采样阶段从样本集粒子中消除大量的粒子。发生这种情况
是因为它们的重要性权重可能变得微不足道。因此，这意味着有一定的小概率时间会消除正
确的假设的粒子。为了避免粒子的退化问题，已经开发了自适应重采样技术。
作者还提出了一种计算精确分布的方法，不仅考虑机器人平台的运动，还考虑最近的观
察。提出了在使用测距运动模 型时结合观测值提出建议分布。然而，当一个移动机器人装
备一个非常精确的传感器LRF时，可以使用该传感器的模型，因为它可以实现了极高的似然
函数。基于此，作者整合了最近的传感器观测zt，并且他们计算高斯分布近似有效 地获得
下一代粒子分布。
（2）HectorSLAM
HectorSLAM是一种结合了鲁棒性较好的扫描匹方法2D SLAM方法和使用惯性传感系统的
导航技术。传感器的要求：高更新频率小测量噪声的激光扫描仪.不需要里程计,使空中无人
机与地面小车在不平坦区域运行存在运用的可能性.作
者利用现代激光雷达的高更新率和
低距离测量噪声，通过扫描匹配实时地对机器人运动进行估计。所以当只有低更新 率的激
光传感器时，即便测距估计很精确，对该系统都会出现一定的问题。
（3） KartoSLAM
KartoSLAM是基于图优化的方法，用高度优化和非迭代 cholesky矩阵进行稀疏系统解耦
作为解．图优化方法利用图的均值表示地图，每个节点表示机器人轨迹的一个位置点和传感
器测量数据集，箭头的指向的连接表示连续机器人位 置点的运动，每个新节点加入，地图
就会依据空间中的节点箭头的约束进行计算更新 .
KartoSLAM的ROS版本，其中采用的稀疏点调整（theSpare Pose Adjustment(SPA)）与
扫描匹配和闭环检测相关landmark越多,内存需求越大,然而图优化方式相比其他方法在大环
境下制图优势更大.在某些情况下KartoSLAM更有效,因为他仅包含点的图(robot pose),求得
位置后再求map.
（4）cartographer
cartographer是Google的实时室内建图项目，传感器安装在背包上面，可以生成分辨率
为5cm的2D格网地图。获得的每一帧laser scan数据，利用scan match在最佳估计位置处插
入子图（submap）中，且scan matching只跟当前 submap有关。在生成一个submap后，会
进行一次局部的回环（loop close），利用分支定位和预先计算的网格，所有submap完成后，
会进行全局的回环。
通过启动ROS下的节点加载对应的SLAM算法，然后控制机器人完成地图构建。

6.3 ROS机器人单点与多点自动导航避障
6.3.1 相关概念概述
ROS的二维导航功能包，简单来说，就是根据输入的里程计等传感器的信息流和机器人的
全局位置，通过导航算法，计算得出安全可靠的机器人速度控制指令。但是，如何在特定的
机器人上实现导航功能包的功能，却是一件较为复杂 的工程。作为导航功能包使用的必要先
决条件，机器人必须运行ROS，发布tf变换树，并发布使用ROS消息类型的传
感器数据。同
时，为了让机器人更好的完成导航任务，开发者还要根据机器人的外形尺寸和性能，配置导
航功能包的 一些参数。
6.3.2 实验目的
熟悉ROS机器人单点与多点自动导航避障步骤。
6.3.3 实验原理
在ROS中，进行导航需要使用到的三个包是：
1、 move_base：根据已有的地图进行路径规划及避障，使移动机器人到达指定的位置。
2、amcl：根据已经有的地图进行定位。
在总体框架图中可以看到，
move_base提供了ROS导航的配置、运行、交互接口，它主
要包括两个部分：
1、全局路径规划（global planner）：根据给定的目标位置进行总体路径的规划，在
ROS的导航中，首先会通过全
局路径规划，计算出机器人到目标位置的全局路线。这一功
能是navfn这个包实现的。navfn通过Dijkstra或A*最优路 径的算法，计算costmap上的最小
花费路径，作为机器人的全局路线。
2、本地实时规划（local planner）：根据附近的障碍物进行躲避路线规划。本地的实
时规划是利用base_local_planner包实现的。该包使用Trajectory Rollout 和Dynamic
Window approaches算法计算机器人每个周 期内应该行驶的速度和角度（dx ，dy ，dtheta
velocities）。base_local_planner这个包通过地图数据，通过算法搜
索到达目标的多条
路经，利用一些评价标准（是否会撞击障碍物，所需要的时间等等）选取最优的路径，并且
计算所 需要的实时速度和角度。
其中， Trajectory Rollout 和Dynamic Window approaches算法的主要思路如下：
1）、采样机器人当前的状态（dx,dy,dtheta）；
2）、针对每个采样的速度，计算机器人以该速度行驶一段时间后的状态，得出一条行驶
的路线。
3）、利用一些评价标准为多条路线打分。
4）、根据打分，选择最优路径。
5）、重复上面过程。

6.4 ROS机器人深度双目与激光雷达构建三维建图与导航
6.4.1 相关概念概述
rtab-map的思想是：假设更频繁的被访问的定位点比其他的定位点更易于形成闭环。这样

到LTM中时，优先选择具有最低权重的定位
点。如果具有最低权重的定位点又有多个时，优
先选择被存储时间最长的那一个。

RTAB-Map整体描述

8.8.2 实验原理
rgbd深度摄像头不仅可以输出rgb图像，由于有结构光的输出，还输出深度数据，这样就
可以获得空间的x,y,z的深度数据，也就是点云数据。这样既然能得到空间的值的，那就可以
利用这个空间值，来计算出目标与机器人小车的距离，这样就可以让小车跟着目标行走。由于
这里只利用到空间值，不对目标物做检测，因此任何目标都可以跟随。

1.协议解析
目前 abot-XARM 采用的机械臂是采用幻尔的 xArm 机械臂。abot-XARM 机械臂控制以
Json 格式方式控制，
Json 易于用户理解，采用的是 value： key 的方式，具体了解用户可以自己百度。分为
三种控制方式:
1. Gripper 夹爪控制，由于夹爪在机械臂中不参与姿态求解，这里用一条单独的指令来进
行控制，控制指令如下：{"abotxArmCmd": 2, "Gripper": 100, "time": 1000}“abotxArmCm
d”是命令集，
2.是夹爪控制， "Gripper "是代表夹爪控制张开闭合大小，xArm 机械臂的夹爪控制范围
是 0-700 的数值,如果传入数值为 0 代表让夹爪闭合，700 代表是张开，
"time"是代表速
度，后面的 1000 是毫秒，也 就是执行此次动作耗时 1000ms 2.姿态控制方式，
姿态控制
方式是以让机械臂运行到空间的 x,y,z 的空间坐标，也就是给一个空间点，
机械臂自动计
算并到达相关的空间点，
指令如下：{"abotxArmCmd": 1, "Pose": {"x": 100,"y":
100,"z": 100,"rotary": 90},"time": 1000}“abotxArmCmd”是命令集，
1 是姿态控制命
令，Pose 是姿态指令集，基为 x,y,z 是代表机械臂相对于机械臂的中心原点为坐标，
规化
到相关的空间坐标，rotary 代表夹爪旋转的角度，取值范围是 0-270 度，"time"是代表速度,
后面的1000 是毫秒，也就是执行此次动作耗时 1000ms，如果用户给出的 x,y,z 超出了机械臂
规化的范围，那么驱动板蜂鸣器会发出滴滴的声音，以告诉用户此值超出了机械 臂的运动范围
（注：用户在给出坐标时，如果底坐高度不一样时，机械臂运行到达的 z 值的高度会随底座的
高度变高而变高，这个用户不需要担心，因为在机械臂求解时，程序设置的底坐高度是参考机械
中心点的那个平面计算的，因此z 值是相对于机械臂中心平面的高度。）
3.按每个舵机的方式控制，
第一条我们的夹爪已经单独来控制了，
这里只控制其它
的相关舵机，每个舵机的取值范围是 0-1000 ，对应映射的角度是 0-270 度，指令如下：{"ab
otxArmCmd": 3, "Trajectory": {"id2": 500, "id3": 500, "id4":500,"id5": 500,"id6":
500}, "time": 1000}“abotxArmCmd”是命令集，
3 是舵机轨迹控制命令，
"Trajector
y "是舵机 的轨迹集，id2-id6是每个舵机的控制步数，这里 id 的序号是夹爪为 id1 依次到
底坐舵机 id6 ，"time"是代表速度，后面 的 1000是毫秒，也就是执行此次动作耗时 1000ms。
2.接线、上电、打开串口发指令
这里我们用串口助手控制示例，以下示例在 win10 与 win7 系统测试过，其它的 windows
系统可能会存在识别不 了串口驱动的问题：接好机械臂并上电，并用一条 Mini USB 线接入
到驱动板上，然后打开串口助手，选择系统识别的串口 ID ，每台电脑识别的 ID 可能不一样，
根据实际情况来选择，如下图：
选择开始按钮，其中相关的串口设置如左侧
将要发送的控制指令，粘贴到发送区域，发送格式选择 ASCII 方式，然后点“发送”，机
械臂会返回相关的数据执行状况，下面的指令代表发送成功 ， 如果机械臂已经上电，那么机械
臂会运行到 x,y,z 都为 100mm 的位置 ， 末端夹爪旋转轴姿态为 90 度，如果报错，请检查
协议有没有发送完整，是否符合 Json 格式。
{"RikibotxArmCmd":1,"Pose":{"x":100,"y":100,"z":100,"rotary":90},"time":1000}

12.7.1 图像阈值化
图像阈值化是将图像从灰度转换为二值化图像的过程，图像的二值化就是将图像上的像素

值图像占有非常重要的地位，图像的二值化 使图像中数据量大为减少，从而能凸显出目标的轮
廓，OpenCV提供了 cv2.threshold() 函数来进行这项操作。
import cv2

cv2.waitKey(0)

12.7.4 HSV颜色分割
我们知道RGB颜色模式，通过不同的配比可以形成不同的颜色。HSV也是一种颜色模式，其
模型如图所示：
通过图示我们也能够看到，他和RGB颜色模型相似，也是由三个属性决定颜色，
H、S、V
分别是色彩、深度、明暗， 按着图中方向的变化，其对应的颜色也会改变，三者也同样是有取
值范围的：
H
（色调）：用角度度量，取值范围为0° ~ 360°
S
（饱和度）：表示颜色接近光谱色的程度。通常取值范围为0% ～100%，值越大，
颜色越饱和。
V
（明度）：表示颜色明亮的程度，对于光源色，明度值与发光体的光亮度有关；对
于物体色，此值和物体的透 射比或反射比有关。通常取值范围为0% （黑）到100% （白）。
HSV空间中三个指标相互独立，能够非常直观
的表达色彩的明暗，色调，以及鲜艳程度，方
便进行颜色之间的对比，所以经常在HSV中进行颜色的分割识
别。在HSV中各个颜色的范围见下表：
说了那么多理论，那对于应用HSV有什么用呢？由于我们可以很直观的通过HSV通道的数值
来确认颜色的范围，因此 当我们需要检测一些单一颜色的目标物时，用HSV做相关目标检测是
最方便的。

12.8.3 目标跟踪
接下来的实战案例是使用MeanShift算法进行目标跟踪。我们将从实时视频中选择一个目
标，然后在后续的帧中跟踪 这个目标。代码如下：
import cv2
import numpy as np
# 打开摄像头
cap = cv2.VideoCapture(0)
# 读取第一帧
ret, frame = cap.read()
# 设置初始的窗口位置
r, h, c, w = 240, 100, 400, 160
track_window =
(c, r, w, h)
# 设置初始的ROI用于跟踪
roi = frame[r:r+h, c:c+w]
hsv_roi = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv_roi, np.array((0., 60.,
32.)), np.array((180., 255., 255.)))
roi_hist = cv2.calcHist([hsv_roi],
[0], mask,
[180],
[0, 180])
cv2.normalize(roi_hist,
roi_hist, 0, 255, cv2.NORM_MINMAX)
# 设置终止条件 ，迭代10次或者至少移动1次
term_crit =
(cv2.TERM_CRITERIA_EPS
| cv2.TERM_CRITERIA_COUNT, 10, 1)
while(True):
ret, frame = cap.read()
if ret == True:
hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
dst = cv2.calcBackProject([hsv],
[0],
roi_hist,
[0, 180], 1)
# 使用MeanShift算法找到新的位置
ret, track_window = cv2.meanShift(dst, track_window, term_crit)
# 在图像上画出新的窗口位置
x, y, w, h = track_window
img2 = cv2.rectangle(frame,
(x, y),
(x+w, y+h), 255, 2)
cv2.imshow('img2', img2)
if cv2.waitKey(1) & 0xFF == ord('q'):
break
else:
break
cap.release()
cv2.destroyAllWindows()

15.1.1 YOLOV5介绍
YOLO是目标检测模型。
目标检测是计算机视觉中比较简单的任务，用来在一张图篇中找到某些特定的物体，
目标检测不仅要求我们识别这些物体的种类，同时要求我们标出这些物体的位置。显然，
类别是离散数据，位置是连续数据。YOLO的全称是you only look once，指只需要浏览
一次就可以识别出图中的物体的类别和位置。因为只需要看一次，YOLO被称为Region-
free方法，相比于Region-based方法，YOLO不需要提前找到可能存在目标的Region。
也就是说，一个典型的Region-base方法的流程是这样的：先通过计算机图形学（或者
深度学习）的方法，对图片进行分析，找出若干个可能存在物体的区域，将这些区域裁
剪下来，放入一个图片分类器中，由分类器分类。因为YOLO这样的Region-free方法只
需要一次扫描，也被称为单阶段（1-stage）模型。Region-based方法方法也被称为两
阶段（2-stage）方法。
15.1.2 实验目的
通过学习YOLOV5两端环境的搭建，实现YOLOV5从训练到部署再到实际应用，就可以
