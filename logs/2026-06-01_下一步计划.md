### 1. 零速注入器节点 ⚡

**问题**: Goal 抢占时 move_base 不发送零速度，机器人靠残留动量滑行

**方案**: 新建 `scripts/goal_preemption_brake.py`，监听 `/move_base/goal`，检测 10s 内连续 goal 变化时立即 publish Twist() 零速

```python
#!/usr/bin/env python
"""Goal 抢占零速注入器"""

import rospy
from geometry_msgs.msg import Twist
from move_base_msgs.msg import MoveBaseActionGoal

class GoalPreemptionBrake:
    def __init__(self):
        self.last_goal_time = rospy.Time(0)
        self.cmd_pub = rospy.Publisher('/cmd_vel', Twist, queue_size=1)
        rospy.Subscriber('/move_base/goal', MoveBaseActionGoal, self.goal_cb)
        
    def goal_cb(self, msg):
        now = msg.header.stamp
        dt = (now - self.last_goal_time).to_sec()
        if 0 < dt < 10.0:
            rospy.loginfo("[BRAKE] Goal 抢占 (dt=%.1fs)，发送零速度", dt)
            self.cmd_pub.publish(Twist())
        self.last_goal_time = now

if __name__ == '__main__':
    rospy.init_node('goal_preemption_brake')
    rospy.spin()
```

**验收**: Goal 2→3 抢占后 cmd_vel 立即归零，无滑行

### 2. waypoint_patrol.py status_list 遍历 bug 🔧

**问题** (`scripts/waypoint_patrol.py:38`):
```python
st = self._status.status_list[0].status  # ← BUG: 永远取第一条
```
move_base status_list 按时间顺序累积，`[0]` 是第一个 goal，`[-1]` 才是当前 goal。中途抢占导致 status_list[0].status=2 (PREEMPTED)，当前 goal 明明是 3 (SUCCEEDED)，却被误判超时。

**修复**: `status_list[0]` → `status_list[-1]`

**验收**: 6 点 patrol 无假超时报错
