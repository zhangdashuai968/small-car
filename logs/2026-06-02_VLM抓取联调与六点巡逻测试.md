## 操作步骤

### 一、VLM 抓取联调

```bash
# ① 底盘+传感器
roslaunch abot bringup.launch

# ② VLM 视觉检测
conda activate 39 && roslaunch vl_locate vl_locate.launch

# ④ 使能抓取

rosservice call /vlm_detection "object_name: 'red'"

```

```bash
# 录制 bag
rosbag record -O ~/bags/patrol_6pt.bag \
  /amcl_pose /raw_odom /odometry/filtered /cmd_vel \

  /tf /tf_static /scan /robot_footprint &

# 跑巡逻
```

## 异常记录

### 异常 1：VLM 节点报 "img_bgr" 属性不存在

- **症状**：`rosservice call /vlm_detection` 报错 `'VLM' object has no attribute 'img_bgr'`
- **排查**：
  1. 检查 `/camera/rgb/image_raw` → 无发布者
  2. 检查 `/camera/gemini` 节点 → 进程已死（exit code 255）
  3. 检查 USB 设备 → 僵尸进程 PID 5111 占用 RGB 摄像头（2bc5:0511）
- **根因**：上一次会话的 gemini camera_node 进程未清理，占用 USB 设备，导致本次 gemini 节点启动失败
- **解决**：`kill -9 5111` → 手动 rosrun 重启 gemini camera_node

### 异常 2：vl_locate 服务类型未编译

- **症状**：`rosservice call /vlm_detection` 报错 `Unable to load type [vl_locate/GetObject]`
- **根因**：vl_locate 包的 srv 消息未编译
- **解决**：`catkin_make --only-pkg-with-deps vl_locate`

### 异常 3：API Key 连续 403

- **症状**：dashscope SDK 返回 403 AccessDenied，三个 key 均报错
- **排查**：
  1. curl 直接测试 → key `sk-4f51e302d219401eb0e21dc9aa7f9bbd` 返回 HTTP 200（key 有效！）
  2. Python requests 测试 OpenAI 兼容模式 → 同样 200
  3. dashscope SDK 测试 → 403
  4. dashscope SDK 测试 openai 模式 → 403（仅限 VL 模型）
- **根因**：
  - dashscope Python SDK（MultiModalConversation.call）有 bug，即使有效 key 也返回 403
  - `qwen-vl-max-latest` 模型该 key 无权限
- **解决**：
  - 切换到 openai 模式（`rosparam set /vlm_detection_node/mode "openai"`）
  - 模型改为 `qwen-vl-max`（经测试 qwen-vl-max ✅，qwen-vl-plus ✅，qwen-vl-max-latest ❌）

### 异常 4：wp2→wp3 导航 ABORTED

- **症状**：车在 wp2 去 wp3 途中原地打转 59s 后 ABORTED
- **排查**：
  1. Bag 分析 AMCL → wp3 开始时 AMCL 位置 (-0.486, -1.598) ≈ wp2，定位准确
  2. Bag 分析 cmd_vel → 最后 10s 纯旋转（mean_ang=0.97 rad/s），前段缓慢移动
  3. Bag 分析 /scan → **前左右三面障碍物均在 0.14m**，后方 1.37m
  4. 排除 EKF 漂移 → AMCL 在 wp2 处定位误差 <0.05m，不是定位问题
- **根因**：**点位 wp2 本身处于狭小空间**，车到达后前左右被障碍物包围（~0.14m），TEB 局部规划器找不到无碰局部轨迹，只能原地旋转寻找通路，最终 oscillation_timeout 触发 ABORTED
- **修正**：此前错误诊断为 EKF/IMU 偏航漂移，实际是环境约束（点位太靠墙）

## 结论

1. **VLM 抓取链路已跑通**：摄像头 → 图像预处理 → VLM 检测 → 机械臂抓取，全链路通过测试
2. **六点巡逻 wp1/wp2 成功，wp3 失败**：根因是 wp2 处于狭小位置（三面障碍物 0.14m），不是 EKF 或定位问题
3. **dashscope SDK 有坑**：建议统一用 openai 兼容模式调用，模型用 `qwen-vl-max`
4. **未解决**：wp2 点位需调整（后移或增加倒车初始动作），P1-P3 计划待推进
