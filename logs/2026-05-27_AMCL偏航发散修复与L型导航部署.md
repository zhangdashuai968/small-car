## 异常记录

### 异常 1：AMCL 不激活（seq=0 卡死）

**症状**：启动 localize.launch 后 `rostopic echo /amcl_pose` 的 header.seq 始终为 0，`/particlecloud` 无输出，tf 不发 map→odom。

**排查过程**：
1. 检查 amcl 日志 → 无报错，节点正常运行
2. 检查 `/scan` → 有数据
3. 检查 amcl 参数 → `update_min_d=0.10m`

**根因**：`update_min_d=0.10m`，车静止时位移 < 10cm，AMCL 滤波器不触发。必须让车动一下超过 10cm 或转一下，AMCL 才开始处理激光数据。

**解法**：通过 `rostopic pub -1 /cmd_vel` 发微动指令（线速度 0.05 或角速度 0.3），触发 AMCL 首次更新。
```
rostopic pub -1 /cmd_vel geometry_msgs/Twist "linear: {x: 0.05}" 
rostopic pub -1 /cmd_vel geometry_msgs/Twist "angular: {z: 0.3}"
```
微动后 `/amcl_pose` seq 从 0 跳到 1，粒子云正常发布。

---

### 异常 2：AMCL 偏航角死区（小角度旋转不更新）

**症状**：车原地转小角度（< 5.7°）时，AMCL 的 yaw 不更新，导致导航脚本的 `_rotate_to()` 转到位后 AMCL 认为没转到。

**根因**：`update_min_a=0.10 rad`（≈5.7°），小于此角度的旋转 AMCL 不做滤波更新。

**解法**：改 `amcl.launch`，`update_min_a` 从 0.10 降到 0.02 rad（≈1.1°）。

```xml
<!-- amcl.launch -->
<param name="update_min_a" value="0.02"/>  <!-- 原 0.10 -->
```

---

### 异常 3（核心）：巡逻 WP3 之后偏差越来越大 — yaw 超 2π 导致 AMCL 粒子发散

**症状**：
- Run 1：WP1/WP2 准确，WP3 开始每点偏差递增，WP6 偏差超 50cm
- AMCL 自报精度显示 3-4cm，但实际位置偏很多（滤波器已发散，自报精度不可信）

**排查过程**：
1. 检查 patrol.yaml 路点坐标 → WP3 yaw=6.6 rad（≈378°），WP4 yaw=5.9 rad（≈338°）
2. 正常 yaw 范围 [-π, π] 即 [-3.14, 3.14]
3. 6.6 rad = 2π + 0.32 rad → 超出一整圈

**根因**：路点标定时用 `rosrun tf tf_echo map base_footprint` 读取的四元数→欧拉角 yaw 值未经归一化，直接写入了 patrol.yaml。AMCL 粒子滤波在 yaw 跨 2π 边界时（导航脚本 `_rotate_to` 调用 `_norm()` 归一化目标 yaw，但中间过程中粒子群在 0 和 2π 之间来回跳），粒子分布发散。

具体来说：
- WP3 target yaw=6.6，脚本 `_rotate_to` 归一化为 6.6-2π=0.32
- AMCL 内部粒子在 6.6 rad 和 0.32 rad 两个等效角度间分裂
- 粒子发散后，map→base_footprint 的 tf 偏移越来越大

**解法**：patrol.yaml 中所有 yaw 手动归一化到 [-π, π]：

| 路点 | 修复前 yaw | 修复后 yaw |
|------|-----------|-----------|
| WP3 | 6.60 rad | 0.32 rad |
| WP4 | 5.90 rad | -0.38 rad |

**教训**：任何时候从 `tf_echo` 或 `amcl_pose` 读四元数存 yaw 时，必须经过 `math.atan2(math.sin(yaw), math.cos(yaw))` 归一化到 [-π, π]。

## 新增功能

### 1. 到达日志（`_drive_to_point` 精度追踪）

每段 leg 到达时打印实际位姿 vs 目标偏差：

```python
rospy.loginfo('    arrived (%.3f,%.3f) yaw=%.2f target=(%.3f,%.3f) err=(%.3f,%.3f) dist=%.3f',
              cur[0], cur[1], cur[2], tx, ty, ex, ey, dist)
```

### 2. wait action（比赛抓取站位停靠）

`do_action()` 新增 `wait` 类型，patrol.yaml 中通过 `duration` 字段设置停靠秒数：

```python
if action == 'wait':
    duration = float(obj) if obj else 0
    if duration > 0:
        rospy.loginfo('  waiting %.1fs ...', duration)
        rospy.sleep(duration)
    return True
```

用法示例（patrol.yaml）：
```yaml
- {name: ROW1_GRASP, frame: map, x: 1.0, y: 2.0, yaw: 0.5, action: wait, object: "10"}
```

## 发现的其他问题

### bringup.launch 需要 5 个环境变量，文档未记录

```bash
export ABOTMODEL=x4          # 车型（x4 = 四轮麦克纳姆）
export CMM_MODE=rosserial    # 通信模式
export ABOTBASE=omni         # 底盘类型（omni = 麦克纳姆轮）
export ABOTIMU=mpu6050       # IMU 型号
export ABOTLIDAR=rplidar     # 激光雷达型号
```

缺少任何一个，bringup.launch 默认值不正确，节点启动失败。

### AMCL 标定精度局限

路点通过"遥控到点 → 读 amcl_pose → 减原点偏移"方式标定，与实际遥控位置偏差 < 10cm。AMCL 自身定位有 ~3-5cm 漂移，加上人工遥控到位精度，累积偏差在可接受范围内。未来建议用激光测距辅助标定。

## 结论

1. **yaw 归一化是今日核心发现**：WP3/WP4 的 yaw 超 2π 导致 AMCL 粒子发散，归一化修复后终点误差从 9.3cm 降到 3.2cm
2. **AMCL 两个关键参数**：`update_min_d`（线位移死区）和 `update_min_a`（角位移死区）直接影响滤波器是否激活
3. **L 型导航（先 X 后 Y）** 对麦克纳姆轮底盘有效：避免了全向斜线运动时的轮子打滑和 yaw 漂移
4. **wait action 就绪**：比赛抓取站位的 10s 停靠功能已实现
5. **下一步**：标定 cargo_handling 比赛路线（6 个路点 + HOME），跑完整比赛流程
