### 振荡链条
```

```

## Goal 3 末段全程低速根因分析 (2026-06-01 傍晚)

### 背景
Goal 3 耗时 23.24s、仅移动 1.46m、全程归类为"微调(<0.16m/s)"。表面看是"末段太慢"，实际是机器人根本没动。

### 直接证据
| 时间 | 事件 | 数据 |
|------|------|------|
| t=0 | Goal 3 发送 | 目标 (-2.79, -2.75)，机器人距目标 1.46m |
| t=0~5s | 惯性滑行 | Goal 2 残留 cmd_vel (v=0.47m/s)，无新指令，机器人漂移 0.82m **远离目标** |
| t=5~11s | 完全静止 | cmd_vel = (0,0,0)，TEB 无任何规划输出 |
| t=11~23s | 纯原地旋转 | cmd_vel = (0,0,ω=1.0 rad/s)，137 条连续纯旋转指令 |
| t=23.24s | Bag 结束 | 机器人距目标仍 1.47m，从未向 Goal 3 移动 |

### 故障链
```
Goal 3 抢占 Goal 2
      │
      ├─[问题1] move_base 抢占 goal 时未发送零速度
      │         → 机器人靠残留动量滑行 5s / 0.82m
      │
      ├─[问题2] 滑行后机器人偏离预期位姿
      │         → TEB 完全停止发布 plan（最后一条发布于 t=+0.02s，之后23秒零输出）
      │         → 局部规划器级故障，不是微调慢
      │
      ├─[问题3] controller_patience=3s → 3s后触发 recovery
      │         planner_patience=3s + max_planning_retries=1
      │         → 仅重试1次后放弃规划
      │
      └─[问题4] recovery 行为链:
                conservative_reset (清 costmap)
                → clearing_rotation (ω=1.0 旋转 12s)
                → 未恢复，bag 结束
```

### 关键配置缺陷
| 参数 | 当前值 | 问题 |
|------|--------|------|
| `max_planning_retries` | 1 | 规划失败只重试一次 |
| `controller_patience` | 3.0s | 滑行期 cmd_vel 仍非零，延误 recovery 触发 |
| `oscillation_recovery_min_duration` | 10s | 旋转恢复最少锁 10 秒 |
| `shrink_horizon_min_duration` | 10s | 缩视野模式最少锁 10 秒 |
| Goal 抢占钩子 | 无 | 无零速度注入机制 |

### 修复方案
1. **参数调优**: `max_planning_retries` 1→3, `oscillation_recovery_min_duration` 10→3, `shrink_horizon_min_duration` 10→3, `controller_patience` 3.0→2.0
2. **零速注入器**（推荐）: goal 抢占时立即发零速度 cmd_vel，消除残留动量滑行
3. **move_base 源码改**: `executeCycle()` 中 new_goal_arrived 时调 `publishZeroVelocity()`

### 对之前结论的修正
| 之前 | 修正 |
|------|------|
| Goal 3 是"末段微调 23s" | 0s 有效运动 + 23s recovery 失败 |
| 路径效率 0% | 根本无路径 — TEB 停摆 |
| 建议调 yaw_goal_tolerance | 不相关 — 不是微调太慢，是压根没动 |
