## 异常记录

### 异常 1：Extrapolation Error（odom→map tf 滞后）— 已解决

**症状**：
```
Extrapolation Error: Lookup would require extrapolation into the future.
Requested time XXX but the latest data is at time YYY.
```
move_base 无法查询 map→odom 变换，导航完全不工作。

**排查过程**：
1. `rosrun tf tf_monitor map odom` → 时间戳严重滞后（1-2秒）
2. `uptime` → load 8.0，4核满载
3. `rosnode list` → 36 节点，Jetson Nano 超载
4. 分析：AMCL 800 粒子 × 180 激光束 = 144k 次计算/周期，4核 Nano 跟不上

**根因**：Jetson Nano 算力不足以在 36 节点负载下实时运行 800 粒子 AMCL + 5Hz costmap。

**解法**：
- AMCL：min_particles 800→100, max_particles 3000→500, laser_max_beams 180→30
- costmap：update_frequency 5→2Hz, transform_tolerance 1.0→3.0s

**效果**：load 8.0→4.34（↓46%），Extrapolation Error 消失。

```bash
# 修复命令：直接编辑车上源文件（rosparam set 在 launch 重启后无效）
vim /home/abot/catkin_ws/src/abot_project/abot/launch/amcl.launch
vim /home/abot/catkin_ws/src/abot_project/abot/param/navigation/common/global_costmap_params.yaml
vim /home/abot/catkin_ws/src/abot_project/abot/param/navigation/common/local_costmap_params.yaml
# 改完后重启 navigate.launch
```

### 异常 2：E05 卡死在 wp1（0.19m 外微调循环）— 未解决

**症状**：
- 车移动到 wp1 附近（距目标 0.19m）后停止
- move_base 状态全程 ACTIVE(1)，持续发 cmd_vel 微调指令
- 6 分钟未到达，手动停止
- cmd_vel 活动比 61%（说明 move_base 一直试图调整）
- 无 SUCCESS(3) 也无 ABORTED(4)

**排查过程**（bag 分析）：
1. `/move_base/status` → 全程 status=1 (ACTIVE)，无 3 (SUCCESS) 无 4 (ABORTED)
2. `/cmd_vel` → 61% 时间有非零指令，说明 move_base 持续工作
3. `/amcl_pose` → 位姿稳定更新，定位正常
4. 最终位置 (-0.30, -2.71) vs 目标 (-0.47, -2.86) → 差 0.19m
5. 对比 6/2 测试：设 xy_goal_tolerance=0.3 时 wp1 67s 成功到达

**根因**：TEB 局部规划器默认 xy_goal_tolerance 过小（~0.1m），在 0.19m 处
无法同时满足位置约束（0.19 > 0.1）、朝向约束、避障约束和全向底盘运动学约束，
陷入无限微调循环。

**解法**：设 `rosparam set /move_base/TebLocalPlannerROS/xy_goal_tolerance 0.3`

```bash
# 临时修复（下次 launch 重启需重新 set）
rosparam set /move_base/TebLocalPlannerROS/xy_goal_tolerance 0.3
```

**长期**：在 teb_local_planner_params.yaml 中固化此参数。

### 异常 3：rosparam set 在 launch 启动后被覆盖 — 踩坑记录

**症状**：先 `rosparam set` 再 `roslaunch`，参数被 launch 文件恢复。

**根因**：launch 文件的 `<param>` 和 `<rosparam>` 标签在节点启动时覆盖参数服务器上的值。

**教训**：改参数必须编辑源文件（YAML / launch），不能依赖 rosparam set。

## 结论

- **P0 参数优化有效**：load ↓46%，Extrapolation Error 消失，导航链路恢复
- **E05 未完成**：TEB 的 xy_goal_tolerance 默认值过小导致 wp1 无法收敛，需改为 0.3
- **load 4.34 仍超 Nano 满载（4.0）**：move_base 方案在 Nano 上已到极限，需切换到 auto_task_runner.py 直驱方案
