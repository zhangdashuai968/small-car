## 异常记录

### 异常 1：gmapping 不发 map→odom，tf 树断开

**症状**：`rosrun tf tf_echo map base_footprint` 报 "map does not exist" / "not part of the same tree"；gmapping 日志首帧 `Laser Pose= -2.41 -15.33`（贴地图下边界 ymin=-15）。

**排查**：`rostopic echo -n1 /odom/pose/pose/position` → x=-2.45, y=-15.35，odom 未归零。

**根因**：odom 跨多次测试累积未重启，机器人"以为"在 15m 外，落在 gmapping 地图窗口 `[-15,15]` 之外，建不出有效图、不发 tf。

**解法**：先关 gmapping → 重启 `bringup.launch`（EKF odom 归零）→ 再起 gmapping，机器人落在地图中心 (0,0)，map→odom 正常。

### 异常 2：建图不实时 + 移动时雷达偏移

**症状**：地图几分钟不刷新；移动/转弯时 `/scan` 红点偏离地图墙体，地图 smeary（双墙、扇形拖影）。

**根因**：gmapping 更新阈值过粗——`map_update_interval=15.0`（每 15s 才重绘）、`linearUpdate/angularUpdate=0.7`（每 0.7m 或 0.7rad≈40° 才 scan-match 一次，间隔靠 odom 推算→漂）、`temporalUpdate=-0.5`（静止不更新，车没走满阈值时图冻数分钟）。

**解法**：改 `param/slam/slam_gmapping.xml`：

| 参数 | 旧 | 新 |
|------|-----|-----|
| map_update_interval | 15.0 | 2.0 |
| linearUpdate | 0.7 | 0.2 |
| angularUpdate | 0.7 | 0.2 |
| temporalUpdate | -0.5 | 2.0 |

**状态：未闭环**。改完 scp + 重启后用户报"仍不实时"，诊断进行中（待确认 `rosparam get /slam_gmapping/map_update_interval` 是否=2.0、文件是否 scp 到位、gmapping 是否真重启、`rostopic hz /map`）。最可能是没重启 gmapping 或 scp 路径不对。

**后续决策**：因 gmapping 实时性反复出问题，转向 **cartographer**（2D + 在线相关性扫描匹配，submap 0.3s 级发布，实时性天生更好）。见下方"cartographer 耦合"。

## cartographer 耦合（gmapping 替代方案）

"耦合" = 时序工作流，**不是同时跑**（cartographer 与 amcl 仍互斥，都最终提供 map→odom）：
```
cartographer 建图(实时) → map_saver 存 comp.pgm/.yaml → amcl(localize.launch) 读图定位
```

**关键修复**：`rplidar_lds.lua` 原配置 `provide_odom_frame=true` + `published_frame=base_footprint` → cartographer 会发整条 `map→odom→base_footprint`，和 bringup 的 EKF（已发 `odom→base_footprint`）**双发冲突**。改为 `published_frame=odom` + `provide_odom_frame=false` → cartographer 只发 `map→odom`，EKF 继续管 `odom→base_footprint`（robot_localization 共存的标准配法）。`use_odometry` 暂保持 false。

**存图**：cartographer 的 `cartographer_occupancy_grid_node` 发 `/map`，与 gmapping 一样直接 `map_saver -f $(rospack find abot)/maps/comp`（不需 .pbstream，除非用 cartographer 纯定位模式）。

**待验证**：scp `rplidar_lds.lua` 后跑阶段1，确认 ① `tf_echo map base_footprint` 有输出（链路 map→odom(carto)→base(EKF)）、② odom→base 不翻倍、③ rviz submap 实时刷新。

---

## 关键结论

1. **两个互斥模式**（都发 `map->odom`，永远二选一）：建图 = `bringup`+gmapping(`lidar_slam`)；已知图导航 = `bringup`+amcl(`localize.launch`)。**不能与 `cartographer_slam`/`navigate.launch` 叠加**（amcl 与 SLAM 抢 map→odom、map_server 抢 /map、lidar 抢串口）。
2. **数据流**：轮速+IMU→[EKF]→odom→base；激光→[gmapping/amcl]→map→odom；合成 map→base 给 `auto_task_runner` 闭环发 cmd_vel。全程不经 move_base/TEB/DWA。
3. **建图原点 = 比赛原点的做法**：不必为挪原点单独重建；重建时把车物理摆到比赛原点、重启 bringup 归零、再起 gmapping，则地图原点=比赛原点=(0,0)，与 `localize.launch` 里 amcl 初值 (0,0,0) 对齐。车头朝向 = 地图 +x 轴。
