## 一句话总结

定位偏差从 9.3cm 降到 3.2cm。核心发现：路点标定时 yaw 值未经归一化写入（6.6 rad 超 2π），导致 AMCL 粒子在 yaw 跨边界后发散。修复后 4 趟巡逻第 4 趟完美收敛，L 型导航 + wait action 为比赛路线就绪。

## 异常记录

### 异常 1：AMCL 不激活（seq=0 卡死）

- **症状**：`/amcl_pose` header.seq=0，粒子云无输出，map→odom tf 不发
- **排查路径**：检查 amcl 日志（无报错）→ 检查 /scan（有数据）→ 检查参数 `update_min_d=0.10m`
- **根因**：车静止位移 < 10cm，AMCL 滤波器不触发
- **修复方式**：通过 `/cmd_vel` 发微动（线速度 0.05 或角速度 0.3），触发首次更新。这是设计行为不是 bug，但需要知道这个条件

### 异常 2（核心）：WP3 之后巡逻偏差越来越大

- **症状**：Run 1 WP1/WP2 准确，WP3 开始偏差递增，终点误差 9.3cm。AMCL 自报精度 3-4cm（但滤波器已发散，自报精度不可信）
- **排查路径**：检查 patrol.yaml → 发现 WP3 yaw=6.6 rad（2π+0.32）、WP4 yaw=5.9 rad（2π-0.38）→ 确认标定时直接从 `tf_echo` 读的四元数→欧拉角，未归一化
- **根因**：yaw 超 2π 导致 AMCL 粒子在 0 和 2π 之间分裂，`_rotate_to()` 的 `_norm()` 归一化目标 yaw 但粒子群已发散，后续路点 map→base_footprint tf 偏移越来越大
- **修复方式**：patrol.yaml 所有 yaw 手动 `atan2(sin, cos)` 归一化到 [-π, π]

```python
rospy.loginfo('    arrived (%.3f,%.3f) yaw=%.2f target=(%.3f,%.3f) err=(%.3f,%.3f) dist=%.3f',
              cur[0], cur[1], cur[2], tx, ty, ex, ey, dist)
```

### 2. wait action（比赛抓取站位停靠）
```python
if action == 'wait':
    duration = float(obj) if obj else 0
    if duration > 0:
        rospy.sleep(duration)
    return True
```
