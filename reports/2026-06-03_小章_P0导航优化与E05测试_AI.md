# AI 会话报告 — P0 导航优化与 E05 六点巡逻测试

## 背景

上次会话（6/2）E05 巡逻 wp3 ABORTED。本次继续排查导航问题，发现 Jetson Nano 扛 35 节点（bringup + vl_locate + navigate）导致 load 飙到 8.0+，AMCL 和 move_base 跟不上实时，odom→map tf 时间戳滞后，触发 Extrapolation Error。

## 优化过程

### 阶段 1：P0 参数优化（不改代码结构）

**目标**：降低 CPU 负载，让 AMCL 和 move_base 在 Nano 上跟得上实时

**改动**（3 文件，7 处）：

| 文件 | 参数 | 旧值 | 新值 |
|------|------|------|------|
| amcl.launch | min_particles | 800 | 100 |
| amcl.launch | max_particles | 3000 | 500 |
| amcl.launch | laser_max_beams | 180 | 30 |
| global_costmap_params.yaml | update_frequency | 5 | 2 |
| global_costmap_params.yaml | transform_tolerance | 1.0 | 3.0 |
| local_costmap_params.yaml | update_frequency | 5 | 2 |
| local_costmap_params.yaml | transform_tolerance | 1.0 | 3.0 |

**踩坑**：rosparam set 在 navigate.launch 启动后无效，launch 文件中的 `<param>` 和 `<rosparam>` 标签会覆盖参数服务器上的值。必须直接改源文件。

**效果**：
- Load: 8.0 → 4.34（↓46%）
- Extrapolation Error 消失
- 导航链路恢复

### 阶段 2：E05 六点巡逻测试

**条件**：
- 33 节点（rviz 关闭）
- P0 参数已固化
- rosbag 录制：/amcl_pose /cmd_vel /move_base/status /move_base/goal /tf /scan /odom
- 用户手动 rviz 2D Pose Estimate 给 AMCL 初始位姿

**结果**：❌ 卡死在 wp1

**详细时间线**（来自 bag 分析）：

| 时间 | AMCL 位姿 | 事件 |
|------|-----------|------|
| 0s | (0.607, -0.381) | 起始，用户给定初始位姿 |
| 28s | (0.181, -1.598) | 向 wp2 方向移动 |
| 46s | (-0.157, -2.699) | 向 wp1 方向移动 |
| 62s | (-0.275, -2.639) | 接近 wp1 |
| 218s | (-0.315, -2.730) | 停留，开始微调 |
| 313s | (-0.321, -2.699) | 仍在微调 |
| 424s | (-0.302, -2.708) | 卡死，手动停止 |

**bag 分析关键数据**：
- cmd_vel 活动比：61%（move_base 持续发命令）
- move_base 状态：全程 ACTIVE(1)，**无 SUCCESS(3) 无 ABORTED(4)**
- wp1 目标：(-0.47, -2.86)，最终位置：(-0.31, -2.73)，**差 0.19m**

## 根因分析

车卡在 wp1 外 0.19m 处，move_base 一直在发 cmd_vel 微调，但始终无法收敛到"满足所有约束"的位姿。

推测 xy_goal_tolerance 默认值过小（可能 0.1m 或更小），TEB 在 0.19m 外无法同时满足：
1. 位置约束（差 0.19m > 0.1m tolerance）
2. 朝向约束（需要精确对准 yaw）
3. 避障约束（附近可能有障碍物）
4. 全向底盘运动学约束

**对比**：上次 6/2 设 xy_goal_tolerance=0.3 时 wp1 67s 成功到达。
