## 异常记录

### 异常 1：Extrapolation Error — 已解决

- **症状**：move_base 报 `Lookup would require extrapolation into the future`，无法规划路径
- **排查路径**：`uptime`→load 8.0 → `rosnode list`→36节点 → 分析 AMCL 计算量(800粒子×180束=144k)
- **根因**：Jetson Nano 4核满载，AMCL 跟不上实时，map→odom tf 时间戳滞后
- **修复方式**：降低 AMCL 粒子数（↓98%），降低 costmap 频率（5→2Hz），放宽 tf 容差（1→3s）

### 异常 2：E05 卡死在 wp1 — 未解决

- **症状**：车到 wp1 外 0.19m 停止，6 分钟内 move_base 持续发 cmd_vel 微调但不收敛
- **排查路径**：bag 分析 → /move_base/status 全程 ACTIVE → /cmd_vel 61% 活跃 → /amcl_pose 稳定 → 距目标 0.19m
- **根因**：xy_goal_tolerance 默认 ~0.1m，TEB 在 0.19m 处无法满足所有约束（位置/朝向/避障），陷入无限微调
- **修复方式**：设 xy_goal_tolerance=0.3（临时 rosparam），长期改 teb_local_planner_params.yaml

### 异常 3：rosparam set 被 launch 覆盖 — 踩坑教训

- **症状**：rosparam set 改参数 → roslaunch 重启 → 参数恢复旧值
- **根因**：launch 文件 `<param>`/`<rosparam>` 在启动时覆盖参数服务器
- **修复方式**：直接编辑源文件，不依赖 rosparam set
