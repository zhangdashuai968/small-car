# AI 会话报告 — DWA 朝向修复与导航测试

## 目标

解决小车到航点后车身往右偏移约 90 度的问题。根因为 `yaw_goal_tolerance: 6.28`（360°）让 DWA 不调朝向。

## 执行的操作序列

1. 诊断：`rosrun tf tf_echo map base_footprint` 确认 AMCL 角度
2. 修改 `dwa_omni_planner_params.yaml`：yaw_goal_tolerance 6.28→0.5, weight_max_vel_theta 80→40
3. 重启 navigate.launch 遇到 action server 不可用（见异常）
4. 多次清理进程/重启后恢复
5. 参数回归原样，再改 yaw_goal_tolerance 6.28→0.3
6. 最终测试：启动四 launch + auto_navigation_grasp.py

|------|--------|------|------|------|

| dwa_omni_planner_params.yaml | weight_max_vel_theta | 80.0 | 40.0 (后还原80) | 降低途中旋转偏好，后来还原 |

## 异常记录

### 异常 1：navigate.launch 重启后 move_base action server 不可用

- **症状**：脚本 `wait_for_server()` 永久阻塞，日志无输出
- **排查路径**：rosnode list 有节点 → ps 找不到进程（zombie）→ lidar 节点重启冲突 → scan 无数据 → AMCL 不工作 → map 帧不存在 → move_base 永远等不到 transform
- **根因**：`killall roslaunch` 只杀了 launch wrapper，nohup 启动的 ROS 节点进程（C++ 可执行文件）存活。新 launch 同名节点冲突退出
- **修复方式**：`killall -9 move_base amcl map_server rosbag` 杀干净，重启 roscore，按序重启四 launch
- **教训**：清进程不能只杀 roslaunch，要杀对应可执行文件；确认 `rosnode list` 返回 "Unable to communicate with master" 才是真清空

### 异常 2：VLM service 返回错误

- **症状**：`Service call failed: 'VLM' object has no attribute 'img_bgr'`
