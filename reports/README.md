# 会话报告系统

## 为什么每次会话结束要写报告？

小车的调试/开发是多人轮流进行的。下一个人（或下一次的自己）需要知道：
- 上一次做了什么、改了什么参数
- 遇到了什么问题、怎么解决的
- 当前小车状态（哪些功能正常、哪些有 bug）

AI 助手（Claude Code / Codex）也需要上下文——AI 看不懂你的聊天记录，但能解析 AI 报告。

## 两份报告的区别

| | 人工报告 | AI 报告 |
|---|---|---|
| **读者** | 人类队友 | AI 助手（下次会话的 AI） |
| **填写人** | 你自己 | AI 生成初稿，你确认 |
| **语言** | 自然中文，可口语化 | 结构化中文 + YAML 字段 |
| **要点** | 做了什么、学到什么、问题是什么 | 状态变更、文件变更、参数变更、待解决 |
| **命名** | `YYYY-MM-DD_执行人_简述.md` | `YYYY-MM-DD_执行人_简述_AI.md` |

## 使用流程

```
会话开始
  ↓
AI 读取最近的 AI 报告恢复上下文
  ↓
你调试/开发，AI 帮你记录关键操作
  ↓
会话结束
  ↓
AI 用 模板_AI报告.md 生成结构化报告初稿
  ↓
你检查 AI 报告，修正不准确的地方
  ↓
你花 5 分钟用 模板_人工报告.md 写一份人类总结
  ↓
两份报告 + 代码变更一起 commit + push
```

## 文件命名示例

```
reports/
├── README.md
├── 模板_人工报告.md
├── 模板_AI报告.md
├── 2026-05-26_小郭_E23_Cartographer调优.md
├── 2026-05-26_小郭_E23_Cartographer调优_AI.md
├── 2026-05-27_小陈_E24_导航避障测试.md
└── 2026-05-27_小陈_E24_导航避障测试_AI.md
```
